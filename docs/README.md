## 核心设计亮点

### 1. OpenHarness架构集成

```
AI助教系统 ←→ OpenHarness框架
├── 诊断流程引擎 ←→ engine/ Agent Loop
├── 多模型仲裁引擎 ←→ tools/ 工具集
├── 变形题生成引擎 ←→ skills/ 知识技能
├── 记忆系统 ←→ memory/ 持久化记忆
└── 知识图谱服务 ←→ coordinator/ 多Agent协调
```

### 2. 90秒闭环诊断流程

```
作业上传 (0s) → 多模态识图 (5s) → 3模型仲裁 (20s) → 
变形题生成 (5s) → 分层诊断 (15s) → 知识图谱更新 (5s)
```

### 3. 三模型仲裁机制

| 模型 | 职责 | 权重 |
|------|------|------|
| GPT-4 (通用) | 题目解构、考点分类 | 0.4 |
| DeepSeek-Math (理科) | 逻辑推演、步骤验证 | 0.4 |
| Llama-3-70B (验证) | 概念映射、归因交叉验证 | 0.2 |

### 4. 记忆系统（OpenHarness风格）

```
student_memory/
├── profile/ (长期认知画像)
├── episodic/ (作业事件流)
├── semantic/ (结构化知识)
└── meta/ (元认知层)
    ├── pending_gaps (24小时观察期)
    └── crystallized (≥30天固化)
```

### 追溯ID体系

| 类型 | ID格式 | 示例 | 数量 |
|------|--------|------|------|
| 功能 | F-{模块}-{序号} | F-UPLOAD-001 | 51个 |
| API | API-{分组}-{序号} | API-HW-001 | 21个 |
| 测试用例 | TC-{模块}-{序号} | TC-UPLOAD-001 | 48个 |
| 开发任务 | TASK-{序号} | TASK-001 | 30个 |

### 追溯矩阵示例

```
功能ID → API ID → 测试用例ID

F-VAR-001 → API-VAR-001 → TC-VARIANT-001,005
```

## 可测性设计

### 测试分层策略

```
单元测试 (60%) → 集成测试 (30%) → E2E测试 (10%)
    ↓                ↓               ↓
自动化率100%    自动化率90%    自动化率80%
```

### 测试覆盖率目标

| 类型 | 目标 | 测量方式 |
|------|------|----------|
| 代码覆盖率 | ≥85% | 自动化测试工具 |
| 功能覆盖率 | 核心功能100% | 功能-测试用例矩阵 |
| 场景覆盖率 | 正常100%，边界≥90% | 测试用例评审 |

### CI/CD质量门禁

```yaml
quality_gates:
  unit_test_pass_rate: 100%
  code_coverage: ">= 85%"
  e2e_critical_paths: 100%
  p90_response: "< 90s"
  model_consensus: ">= 80%"
```

## 开发计划

### Sprint规划

| Sprint | 周期 | 功能 | 工时 | 产出 |
|--------|------|------|------|------|
| Sprint 1 | Week 1-2 | 基础架构 | 12人天 | 数据层+上传 |
| Sprint 2 | Week 3-4 | 核心诊断 | 13人天 | 三模型仲裁 |
| Sprint 3 | Week 5-6 | 变形题+分层 | 12人天 | 诊断闭环 |
| Sprint 4 | Week 7-8 | 记忆+统计 | 11人天 | 知识图谱 |
| Sprint 5 | Week 9-10 | 冷启动+优化 | 12人天 | MVP完成 |

### MVP功能清单（P0 - 44人天）

- [x] 作业上传（拍照+描述）
- [x] 图片预处理（压缩/去噪）
- [x] 三模型并行推理

- [x] 错题识别
- [x] 数值变形生成
- [x] 变形题答题验证
